# Implemented capabilities and evidence

This is a source-built derivative of selected public Caveman v4.0.1 local components plus an independently implemented Traqiva application. It is not the complete Caveman product. The comparison below uses the [pinned upstream README](https://github.com/JuliusBrussee/caveman/blob/v4.0.1/README.md), [licensing statement](https://github.com/JuliusBrussee/caveman/blob/v4.0.1/LICENSING.md) and the actual code delivered here. Upstream's published benchmark numbers are not Traqiva measurements.

## Current release scope

The current product is for coding agents. `src/features/agentBuilder.ts` holds the shared browser/Worker release capability `AGENT_BUILDER_ENABLED=false`; there is no customer-facing switch. Application-builder goals, API/SDK onboarding, evaluation navigation/routes, matching Inbox items and the seven evaluation demo modules are hidden. `/api/evals*` is not registered. Builder setup components and evaluation implementations remain separate in source for a future release. Common request recording, project keys, native/CLI connection, compression, Auto and Waste checks remain available because coding integrations use them too. Enabling the capability requires building and deploying both frontend and Worker together; enabled-path tests remain in the suite.

Onboarding flow version 2 starts new registrations at Step 1. Migration `0007` only adds an internal version column. On the next authenticated session read, an older unfinished flow returns once to Step 1 while keeping its project, traffic and consent. Current confirmed progress resumes after refresh/login, and completed accounts continue to their workspace. An unfinished disabled application-builder goal must be reconfirmed as a coding setup. Project setup cannot bypass this confirmation.

Stage 3 shows one short, universal AI setup prompt directly. There is no assistant picker, manual command block or More setup options accordion in that step. The copy includes only the service URL and project ID, with instructions to follow the public `/agent-setup.md` guide. A small Project key button opens the existing private-key generator; neither the prompt nor its clipboard copy contains a key. Consent, real connection detection, disabled Continue until connected and explicit Skip remain unchanged. The guide supports Codex CLI/desktop and Claude Code through their supported local STDIO MCP setup, while preserving other settings. Installation, client restart and active MCP tool checks still must be performed by the receiving agent; copying a prompt is not proof of a working connection or token savings.

Local browser verification checked the real 577-character clipboard text, absence of the old accordion/commands, the Project key dialog and a 390×844 content viewport without horizontal overflow. A local-only delayed mock of key creation confirmed Escape cannot discard an in-flight one-time response and the dialog closes normally after completion. That mock created no real credential. The plain application had no warning/error logs. The temporary harness was removed before building. Twenty-five isolated CLI/native/setup tests also passed, including actual Windows native exact recovery; no real desktop MCP configuration, provider or paid model call was changed or invoked.

The planned overage policy pauses an exhausted product until the next month; a future card option uses standard rates with a $50 monthly cap per product, and one gateway event per started 64 KB sent. This release has no hosted quota ledger, run-minute meter, sponsored AI credit, card collection, automatic pausing, paid subscription or Team trial implementation. ## Six efficiency controls in CLI 0.2.0

These are the implemented equivalents of the six requested capability categories, not a claim to reproduce Caveman's private services. Local controls are stored on the user's device; the web application cannot read their status. Auto and Waste checks are independent per-project settings on the Worker.

| Control | Working implementation | Boundary and default |
| --- | --- | --- |
| Say Less | Optional concise-response guidance in MCP initialization instructions and instruction injection on supported calls through the local API-key bridge | Off by default. Host/model compliance is not enforced, and detailed user requests must still be respected. Does not rewrite an existing desktop conversation or the native child-proxy path; no general output-token reduction is measured |
| Read Less | Existing recoverable native artifact compression, explicit CLI/MCP calls and recovery-gated native Codex child proxy | On by default. Turning it off disables new CLI/MCP compression and launches the native child in record-only mode, preserving request input. Recovery remains available. Supported content may lose model-visible detail; retrieve the source when needed. Does not intercept every installed assistant |
| Auto | Opt-in `traqiva-auto` gateway model selects one of three owner-configured models and optional low/medium/high reasoning efforts; actual trace records carry the tier and decision reason | Off by default. Only OpenAI Responses and Chat Completions, using the fixed OpenAI upstream. Policy is deterministic request-size/task-hint routing, not a trained or quality-validated cheapest-correct router. Explicit model names and explicit effort are preserved. Users must choose compatible models/efforts; no paid compatibility probe or fallback retry is automatic. Auto costs remain unknown because one request-level price cannot describe three possible models |
| Blocks | Private local, immutable script records with SHA-256 checks; CLI/MCP save, metadata search, exact retrieval and explicit deletion | On by default. Stores code as data and never executes it. Reuse requires the agent/user to retrieve and use a saved script; it is not autonomous code deployment or a shared cloud memory service |
| Waste Fixes | Recorded-trace rules for errors, unknown prices, large inputs, repeated leading instructions and low cache coverage; manual analysis plus the existing optional scheduled-suggestion path | On by default, independently switchable. New prefix/cache checks inspect at most 200 retained requests from the last 7 days, excluding future records; payload reads are bounded to 65,536 characters. Findings include trace IDs and measurement limits, not verified savings. Acceptance records review status and does not change provider cache configuration or deploy a fix |
| Browse | Local public HTTP(S) HTML/text fetch, static text extraction and compression, source URLs/digests and exact retained-source recovery | On by default. DNS-pinned public addresses and redirect checks; no JavaScript rendering, browser cookies, private login or general search engine. Recovered `original_base64` supplies exact downloaded bytes. Extracted/compacted text may omit source detail; preserve the local source store |

`traqiva controls status` reports actual local state. `traqiva controls set say-less|read-less|blocks|browse on|off` changes one local control. After changing Say Less, restart the MCP session so its initialization instruction is refreshed. Recovery tools remain usable after disabling new compression/Browse work. Configure project Auto/Waste settings in **Efficiency controls**; they do not silently change local files or enable routing in an existing desktop chat.

The [official OpenAI reasoning guide](https://developers.openai.com/api/docs/guides/reasoning) distinguishes Responses `reasoning.effort` from Chat Completions `reasoning_effort`; accepted effort values and defaults depend on the selected model. Traqiva's policy does not discover that compatibility on the user's behalf.

## Platform capabilities

| Capability | Traqiva implementation | Practical boundary |
| --- | --- | --- |
| Local compression engine | Selected Apache-2.0 engine, tokenizers, compressors and persistent content recovery; independent Traqiva entry point | Input-dependent. CGO disabled; structural code compression supports Go, not the complete tree-sitter language set |
| Exact recovery / MCP | Node CLI, local CCR database, `traqiva_retrieve`; `compress`, `recover` and MCP tools | Native text stays local; handles require the matching retained local database. Cloud JSON fallback stores an authorized project artifact on your Worker |
| One-command local setup | Hosted `/cli.tgz` runs the CLI 0.2.0 interactive wizard through npx; checksum-verified engine, stable user-local client, optional official-CLI MCP registration or printed settings | Requires Node.js 22.13+ and confirmation in the terminal. Preserves existing same-name MCP settings. Registration is configuration only: restart/load tools separately; does not enable Auto, desktop interception or a cloud project connection |
| Request proxy | Public native proxy fork, forced commercial Cloud offline; explicit child Codex/Claude CLI launchers | Experimental. Does not modify global config or intercept an existing desktop conversation. Claude launcher has no end-to-end validation |
| API gateway and provider usage | OpenAI Responses/Chat Completions and Anthropic Messages; SSE passthrough, provider counters when reported | Requires a user's API key; missing usage is unavailable, not zero; no arbitrary upstream-host proxy |
| Traces and analytics | D1-backed projects, request traces, token/cost metadata and filters | Only connected/imported traffic is visible. A dashboard cannot infer unseen desktop requests |
| Developer sessions | Tenant-scoped explicit-session aggregation, project/date/search/model controls, display columns and pagination | Requires `request.session_id`, `request.metadata.traqiva_session_id` or `request.metadata.session_id`; reads at most 200 recent SDK/gateway/native-proxy candidates and flags truncation. Imports/assistant/compression events do not become sessions. Mixed estimated or missing usage stays unavailable; prices are supplied subtotals, not invoices |
| Compression events | Separate estimated token/byte event table, native metadata upload and JSON minification lab | Events are not provider requests. Local estimates are not billing reductions |
| Improvements | Deterministic recorded-traffic checks with bounded leading-prefix/cache evidence and an independent Waste switch | Suggestions, not a continuous self-optimizing model or proof a recommended change was deployed |
| Verified savings | Display of evidence status and measurement boundaries; narrow explicit-input token A/B below | No invoice verification or general coding-quality benchmark; no measured automatic desktop reduction |
| Evaluations | Implementation retained behind the disabled application-builder capability | Not exposed in this release; page redirects and APIs return 404. Historical enabled-path checks below are not a current availability claim |
| Ask | BYOK OpenAI/Anthropic question answering over selected project metadata | Explicit calls only, user's provider billing; not server-sponsored or automatically running |
| Authentication and projects | Email/password, Google OIDC, GitHub OAuth, explicit social account linking, workspace/project membership, project keys, onboarding | Each social provider needs the deployment owner's own OAuth client. Email ownership verification/reset mail, SSO/passkeys and commercial billing are not implemented |
| Public interactive demo | Homepage embed and anonymous `/demo` tour with 11 coding-focused sample modules, inspectable metrics/day charts, workflow drilldowns, evidence-to-trace navigation, local brief review and reset | Bundled fictional records only. Example keys cannot authenticate. Seven builder/evaluation modules are disabled, including their direct links. Ask computes preset answers from the selected period; no model/provider or project mutation calls originate from the demo |
| Model/effort routing | User-selected models pass through; explicit `traqiva-auto` requests use saved model/effort tiers | OpenAI-only deterministic policy with no model-market search, trained quality router or cheapest-correct guarantee |
| Other upstream components | No claim | Complete assistant hooks, proprietary quality graders, commercial routing, organization/credits/billing and causal savings infrastructure are not reproduced |
