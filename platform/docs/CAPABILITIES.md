# Implemented capabilities and evidence

This is a source-built derivative of selected public Caveman v4.0.1 local components plus an independently implemented Traqiva application. It is not the complete Caveman product. The comparison below uses the [pinned upstream README](https://github.com/JuliusBrussee/caveman/blob/v4.0.1/README.md), [licensing statement](https://github.com/JuliusBrussee/caveman/blob/v4.0.1/LICENSING.md) and the actual code delivered here. Upstream's published benchmark numbers are not Traqiva measurements.

| Capability | Traqiva implementation | Practical boundary |
| --- | --- | --- |
| Local compression engine | Selected Apache-2.0 engine, tokenizers, compressors and persistent content recovery; independent Traqiva entry point | Input-dependent. CGO disabled; structural code compression supports Go, not the complete tree-sitter language set |
| Exact recovery / MCP | Node CLI, local CCR database, `traqiva_retrieve`; `compress`, `recover` and MCP tools | Native text stays local; handles require the matching retained local database. Cloud JSON fallback stores an authorized project artifact on your Worker |
| One-command local setup | Hosted `/cli.tgz` runs the CLI 0.1.1 interactive wizard through npx; checksum-verified engine, stable user-local client, optional official-CLI MCP registration or printed settings | Requires Node.js 22.13+ and confirmation in the terminal. Preserves existing same-name MCP settings. Registration is configuration only: restart/load tools separately; no automatic model routing, desktop interception or cloud project connection |
| Request proxy | Public native proxy fork, forced commercial Cloud offline; explicit child Codex CLI launcher | Experimental. Does not modify global config or intercept an existing desktop conversation. Claude automatic launcher not implemented |
| API gateway and provider usage | OpenAI Responses/Chat Completions and Anthropic Messages; SSE passthrough, provider counters when reported | Requires a user's API key; missing usage is unavailable, not zero; no arbitrary upstream-host proxy |
| Traces and analytics | D1-backed projects, request traces, token/cost metadata and filters | Only connected/imported traffic is visible. A dashboard cannot infer unseen desktop requests |
| Developer sessions | Tenant-scoped explicit-session aggregation, project/date/search/model controls, display columns and pagination | Requires `request.session_id`, `request.metadata.traqiva_session_id` or `request.metadata.session_id`; reads at most 200 recent SDK/gateway/native-proxy candidates and flags truncation. Imports/assistant/compression events do not become sessions. Mixed estimated or missing usage stays unavailable; prices are supplied subtotals, not invoices |
| Compression events | Separate estimated token/byte event table, native metadata upload and JSON minification lab | Events are not provider requests. Local estimates are not billing reductions |
| Improvements | Deterministic metadata checks for repetition, error rates and cache candidates | Suggestions, not a continuous self-optimizing model or proof a recommended change was deployed |
| Verified savings | Display of evidence status and measurement boundaries; narrow explicit-input token A/B below | No invoice verification or general coding-quality benchmark; no measured automatic desktop reduction |
| Evaluations | User-defined exact-match cases, runs and recorded outcomes | Not a general semantic-quality evaluator or Caveman Cloud's full evaluation service |
| Ask | BYOK OpenAI/Anthropic question answering over selected project metadata | Explicit calls only, user's provider billing; not server-sponsored or automatically running |
| Authentication and projects | Email/password, Google OIDC, GitHub OAuth, explicit social account linking, workspace/project membership, project keys, onboarding | Each social provider needs the deployment owner's own OAuth client. Email ownership verification/reset mail, SSO/passkeys and commercial billing are not implemented |
| Public interactive demo | Homepage embed and anonymous `/demo` tour with 18 navigable sample modules, trace filtering/details, local brief review, editable exact-match cases, charts and reset | Bundled fictional records only. Example keys cannot authenticate. Ask uses preset answers. Monitors, governance, scenarios and quality gates are local previews, not new backend capabilities; no model/provider or project mutation calls originate from the demo |
| Model/effort routing | User-selected model forwarded | Automatic “cheapest correct model” / effort routing is not implemented |
| Other upstream components | No claim | “Say less” voice integration, complete read-less hooks, Blocks/memory, browse, commercial organization/credits/billing ecosystem are not reproduced |

## Actual checks

The 2026-10-22 quickstart was tested from the real hosted tarball in a Windows interactive terminal with an empty npm cache and isolated Traqiva directory. The advertised npx command opens the wizard; Local files plus confirmation installed the checked native engine and persistent CLI 0.1.1. A 13,942-byte synthetic log compressed locally and recovered byte-for-byte; the installed MCP server listed compression, retrieval and stats tools. No cloud connection or provider call was created. Codex/Claude registration, preservation and failure paths were tested with isolated fake assistant subprocesses, not the user's real assistant configuration. Windows native executables and official npm JS entry resolution were exercised with filesystem/process fixtures. A registry audit request stalled in the initial host test, so the command explicitly uses per-invocation `--no-audit` for this dependency-free package; no npm configuration is changed and native integrity checks remain mandatory. Vite's automatic gzip decoding was reproduced and fixed by proxying local downloads through the Worker; localhost and production archive hashes then matched the manifest.

The white Get started panel keeps the reference's CLI/Cloud layout and now copies one executable command from the entire command box. Browser checks covered the real copied text, confirmation feedback, desktop 1280×820 and mobile 390×844 content viewports, and Escape focus restoration. An isolated temporary iframe was used for viewport checks and removed before building. Browser warning/error logs were empty. Real-client MCP registration, Linux/macOS execution and actual model token/billing savings remain unverified by this release.

The 2026-10-21 public demo was researched by opening the reference site's live demo and inspecting Home, Traces/details, Improvements, Experiments and Governance. The supplied screenshot and the rendered Traqiva demo were compared with `view_image`: sidebar grouping, breadcrumb header, five-card overview, blue/green charts, Geist typography and the permanent fictional-data footer retain the reference's structure. Intentional differences are Traqiva branding, white-first theme, original sample fixtures and cache coverage instead of an invented verified monetary saving. Advanced features are visibly marked as previews. The reference-sized 1326×778 and mobile 390×844 content viewports were checked in an isolated local iframe harness because the in-app browser does not expose viewport resizing; document width matched each viewport. The temporary harness was removed before building.

In-app browser checks exercised the homepage anchor/full-screen entry, 7/30-day totals, analytics chart switching, trace search/model/status filtering and Request/Response, brief review and open counts, sessions-to-trace navigation, Inbox dismissal, all evaluation submodules, settings/theme synchronization, Reset and mobile navigation/Escape focus. Editing the retention case from `30 days` to `30` changed the local result from 67% to 100%; Reset restored the original fixture. Quality-gate thresholds changed the preview result, while a 2,500ms monitor threshold correctly matched no sample traces. Demo state has no API/context/storage dependency; the site's existing account-provider session bootstrap remains separate. The local Worker logged session lookups only during this tour: no demo project writes or model requests. Browser warning/error logs were empty. All 172 application tests, lint, TypeScript and the production build passed. The demo is a separate lazy-loaded bundle (15.51KB gzip) and loads near its homepage section.

The 2026-10-21 Sessions layout was compared directly with the supplied desktop reference through the in-app browser. The shared shell, product switcher, breadcrumb header, filter row, four 105px metric cards, 1350px-wide/540px-high panel and footer pagination follow the reference structure. Geist Sans/Mono remain self-hosted; dark surfaces use neutral gray instead of purple. White remains the default theme. The 1910×911 and 390×844 content viewports were checked in a temporary same-origin iframe harness because the browser tool does not expose viewport resizing; the desktop preview was scaled only for capture, and its measured content viewport remained 1910px with no page-width overflow. The temporary harness was removed before the production build.

Local browser verification used 23 synthetic sessions in an isolated D1 store, without provider calls or production records. It exercised search, model filtering, display columns, two-page navigation, project/product switching, Home/Gateway navigation, the closed compression tools, theme switching and mobile navigation with Escape focus restoration. Browser warning/error logs were empty. All 156 application tests, lint, TypeScript and the production build passed. Intentional differences from the reference: Traqiva branding; default light theme; concise evidence-based empty copy and connection status; Project usage includes all project traffic; unsupported Individual/Repositories/Delivery/Your agents/actor filtering are disabled; original local compression remains available under a closed disclosure. No reference quota, refresh timestamp, savings or traffic was invented.

On 2026-10-21 the hosted release completed real GitHub consent with only `read:user user:email`, explicit linking to an existing Google account, sign-out, and GitHub sign-in. The authenticated user, workspace, active project and project count stayed the same; both provider links persisted. New-account creation and failure paths were checked through controlled OAuth tests, not a second live GitHub identity. The final application suite passed 125 tests, alongside lint, TypeScript and the production build. See [GitHub setup and verification](GITHUB_AUTH.md).

On 2026-10-21 a four-run real Codex A/B test used the same `gpt-6.1-sol / ultra` and synthetic extraction task in A→B→B→A order. Explicitly supplying the Traqiva-compressed log reduced Codex-reported input from **20,756 to 14,681 tokens (29.27%)**, with all five required facts correct in every run and zero cached-input tokens. Mean input plus output fell **29.13%**. This is one explicit-precompression task, not automatic desktop or billing savings. The automatic file-reading control was blocked by its child execution policy, so that path has no completed A/B result. See the [complete measurement and reproduction record](TOKEN_USAGE_AB_TEST.md).

On 2026-10-20 a clean Windows CLI installation downloaded the native engine from the deployed HTTPS manifest, verified its archive SHA-256 and compressed a synthetic 240-line log containing a unique error. Input **15,429 bytes**, output **467 bytes**, offline BPE estimates **5,304 → 141 tokens**. Recovery returned the original byte for byte, checked with Node Buffers. No provider/model call occurred. This demonstrates recoverable local compression on that fixture; it does not measure a complete agent session, semantic task quality or a bill reduction.

A separate real Codex ChatGPT session successfully routed two Responses requests through the experimental proxy and returned the correct synthetic result. Both requests used the safe `recovery_unproven` passthrough path: **zero transformations**. Provider usage was unavailable. The global Codex config hash remained unchanged and authentication files were not copied. Routing succeeded; subscription token savings were not demonstrated.

Local mock-upstream tests also demonstrate conversion of an eligible tool response, byte-exact SSE passthrough and matching CCR recovery. A mock is useful for regression testing and is not a real-model quality or billing experiment. Linux amd64 and macOS arm64 artifacts were cross-compiled, not executed in this validation environment.

The complete upstream test suite is not reported as passing. In no-CGO builds the upstream release-shape test expects TypeScript/JavaScript/Python parsers not present here; CloudLink's online-cache test is incompatible with forced-offline policy. Selected entrypoint, CCR, compressors, tokenizer, OpenAI/Anthropic provider and Traqiva offline-guard tests passed. See [native verification](../runtime/VERIFICATION.md).
